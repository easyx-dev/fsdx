 # CMS 系统设计
 
 ## 技术栈
 
 TanStack Start (SSR) + React 19 + TanStack Router + TypeScript 6 + Vite 8 + Tailwind CSS 4 + shadcn/ui (new-york) + Drizzle ORM + PostgreSQL
 
 ## 架构
 
 管理端和客户端共用一个 TanStack Start 实例，通过路由前缀 /admin 和 / 区分。管理端 CSR，前台 SSR。
 
 ## 鉴权
 
 - JWT (access + refresh token)，httpOnly Cookie
 - 客户端用户邮箱验证码注册
 - 管理端权限码硬编码，role 表 permissions 字段 (jsonb) 存储角色拥有的权限码列表
 - admin_user 通过 role_id 关联单一角色
 
 ## 软删除约定
 
 - 所有支持删除的表统一加 deleted_at 字段
 - 查询默认 WHERE deleted_at IS NULL
 - 删除操作设置 deleted_at = now()
 - captcha_code 不设软删除（临时消耗型记录）
 
 ## 成熟库选型
 
 日志：pino + pino-roll（高性能结构化日志，按天切割）
 定时任务：node-cron（轻量 cron 表达式调度）
 邮件：nodemailer（Node.js 邮件发送标准库）
 JWT：jose（轻量 JWT 库）
 密码加密：bcryptjs（纯 JS 实现）
 
 ## 模块清单（10 个）
 
 1. 日志模块 - pino + pino-roll，按天切割，管理端可搜索 .log 文件
 2. 管理员用户 + RBAC - admin_user, role，权限码硬编码
 3. 客户端用户 - client_user，邮箱验证码注册
 4. 验证码模块 - captcha_code，60s 频率限制
 5. 字典管理 - dict, dict_item，内存 Map 缓存
 6. 系统配置 - system_config，内存 Map 缓存
 7. 文件管理 - file，SHA256 秒传，存储抽象层
 8. 新闻管理 - news，TipTap 富文本，前台 SSR
 9. 定时任务 - node-cron
 10. 仪表盘 - 统计查询
 
 ## 权限码常量
 
 news:view / news:create / news:edit / news:delete
 admin:view / admin:create / admin:edit / admin:delete
 client:view
 role:view / role:create / role:edit / role:delete
 dict:view / dict:edit
 config:view / config:edit
 file:view / file:upload / file:delete
 log:view
 dashboard:view
 
 ## 路由结构
 
 - / 前台首页（新闻列表 SSR）
 - /news/$slug 新闻详情（SSR）
 - /admin/login 管理员登录
 - /admin/ 仪表盘
 - /admin/news/ 新闻管理
 - /admin/users/admins/ 管理员列表
 - /admin/users/clients/ 客户端用户列表
 - /admin/roles/ 角色管理
 - /admin/dicts/ 字典管理
 - /admin/config/ 系统配置
 - /admin/files/ 文件管理
 - /admin/logs/ 日志查询
 
 ## 实现阶段
 
 阶段 1（0 表）基础设施：pino + pino-roll、node-cron、内存缓存、存储抽象、JWT、邮件、中间件、权限码
 阶段 2（4 表）admin_user + role + client_user + captcha_code + 登录注册
 阶段 3（3 表）dict + dict_item + system_config + 缓存
 阶段 4（1 表）file + 秒传 + 临时文件 + 过期清理
 阶段 5（1 表）news + 管理端 CRUD + 前台 SSR
 阶段 6（0 表）仪表盘 + 管理端日志查询
